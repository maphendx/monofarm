# RemOnline (RO App) — розбір фіч під warehouse-модуль monofarm

> Дослідження живого акаунта `web.roapp.io` (2026-07-03). RemOnline — CRM для сервісних
> бізнесів з повноцінним складом/ERP. Мета документа — виписати круті фічі та зіставити
> з тим, що вже є в monofarm, щоб спланувати доробки.

Легенда: ✅ вже є · ⚠️ частково · ❌ гап

---

## 🏭 Склад — ядро

RemOnline тримає весь облік як **документи-операції** (кожна дія = окремий документ з
історією), а не просто зміну числа.

| Операція RemOnline | Що це | monofarm |
|---|---|---|
| Залишки | поточні залишки по складу / категорії / доступності | ✅ `StockEntry` |
| **Партії (лоти)** | кожне оприбуткування = окрема партія з власною ціною закупки, постачальником і терміном придатності | ❌ гап |
| Оприбуткування | прихід товару документом | ✅ `PURCHASE_IN` |
| **Резервування** | окрема вкладка-реєстр усіх резервів | ⚠️ резерв у ордері, немає загального реєстру |
| **Конвертації** | перетворення товару в інший (розпаковка bulk→штуки, розбір комплекту) | ❌ гап (є production batch, але важче) |
| Переміщення | між складами | ✅ `TRANSFER` |
| Інвентаризації | звірка факт/облік | ✅ stocktake-сесії (2026-07-02) |
| Списання | write-off | ✅ `WRITE_OFF` |
| **Повернення** | окремо: від клієнта + постачальнику, документом | ⚠️ є `RETURN_IN`, але не workflow-документ |
| **Замовлення постачальникам (PO)** | документ закупівлі + 2 авто-списки | ❌ гап |

**Найцінніше з PO-дропдауна (automation):**
- **Товари під замовлення клієнтів** — авто-бекордер: збирає, що докупити під відкриті ордери.
- **Товари для поповнення залишків** — авто-реордер за мін. залишком: готовий список «що замовити».

## 📦 Картка товару

Поля RO: тип (шаблон), категорія, опис, одиниця виміру, код, артикул, **кілька штрихкодів**
(+ генерація EAN-баркоду), **габарити та вага**, фото.

Вкладки картки: Загальні · **Партії** · Історія руху · Замовлення постачальнику · Залишки по складах.

**Гапи для нас:**
- 🔥 **Багаторівневі ціни**: Нульова / Оптова / Ремонтна / Роздрібна — 4 цінові рівні на товар.
  У нас `cost_price` + `sale_price` (2). Для B2B/опт/роздріб — велика фіча.
- **Кілька штрихкодів** на товар + вбудований генератор EAN.
- **Габарити + вага** (пакування/доставка).
- **Термін придатності** на партії → звіт «скоро протермінується».

## 💰 Фінанси — мульти-каса (ширше за наш CashFlow)

- **Кілька іменованих рахунків**: Банк / Готівка / Кредитна картка — кожен зі своїм балансом.
- Операції: Надходження · Витрата · **Переміщення між рахунками**.
- **Теги** на транзакціях (аналітика по тегах).
- **Взаєморозрахунки** — баланс боргів з контрагентами (у нас `Counterparty.balance` є, але без окремого реєстру).
- Платіжні посилання, Відшкодування, Зарплата (payroll — імовірно поза скоупом).

У нас `CashTransaction` = одна умовна каса. **Гап: мультирахунки + переміщення + теги.**

---

## 🛒 Продажі (швидкий POS)

Окремий від «Замовлень» потік: продати в кілька кліків — обрати склад, клієнта, кинути
товари, сума. Списує зі складу одразу. У нас важкий `Order` (reserve→ship); легкого
касового продажу немає — **варто додати** для роздрібу/швидких відвантажень.

---

## 👥 Контакти — сегментація за LTV

Фільтри контактів: тип, менеджер, тег, к-сть замовлень, сума замовлень, к-сть продажів,
сума продажів, вік, день народження. Тобто «покажи клієнтів з >N замовлень на суму >X»
в один клік — готова база для «топ-клієнти / хто приносить прибуток». У нас контрагенти простіші.

## 📊 Звіти — окремий рушій

- **Складські:** Обороти товарів · **Форма обліку товарних запасів** (формальний друкований
  журнал) · Залишки · Списання · **Товари що потребують закупівлі** · **Термін придатності**.
- **Фінансові:** Всього грошей · Рух коштів · **Прибуток від замовлень** vs **Прибуток від
  продажів** (окремо!) · Розрахунок податків.
- Плюс: **Аналіз асортименту** (ABC-подібний), **Аналітичний звіт**, і 🔥 **Журнал подій** —
  повний audit-log усіх дій, фільтр по співробітнику/періоду/типу події.

У нас turnover/customers/margin вже є (2026-07-02), але **audit-log компанії** та **прибуток
окремо по продажах vs ордерах** — гапи.

## 🎯 Пріоритетний беклог доробок

**Топ-value (близько до наших даних, велика віддача):**
1. **Багаторівневі ціни** на товар (opt/retail/спец) — розширити `Product`.
2. **Партії/лоти з ціною закупки + термін придатності** → точний FIFO-костинг + expiry-звіт (зараз AVCO).
3. **Замовлення постачальникам (PO)** + авто-реордер за мін. залишком + бекордер під ордери.
4. **Резервування** як окремий реєстр (не тільки всередині ордера).
5. **Журнал подій (audit-log)** по всьому складу/фінансах.

**Середній пріоритет:**
6. **Мульти-каса** у Фінансах + переміщення між рахунками + теги транзакцій.
7. **Швидкий POS-продаж** (окремо від важкого Order).
8. **Повернення** як документ-workflow (клієнт / постачальник).
9. **Конвертації** товару (bulk→штуки, розбір комплекту).
10. **Сегментація контрагентів** за LTV / к-стю замовлень.

**Дрібне, але приємне:**
11. Кілька штрихкодів + генератор EAN.
12. Габарити/вага товару.
13. «Форма обліку товарних запасів» — друкований складський журнал.

---

**Рекомендація для старту:** почати з #1 (багаторівневі ціни) або #3 (PO + авто-реордер) —
найдешевші при найбільшій віддачі.
